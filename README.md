### Francisco Olmedo

**Physicist. I build backend and AI systems that have to work outside a demo.**

Physics taught me to ask what is actually being measured. I bring the same
habit to software: make the system understandable, test the important parts,
and find out where it breaks before calling it done.

**Currently**<br>
— Lead AI Engineer @ Hagalink — backend, agents and applied AI<br>
— PhD candidate in applied AI @ Universidad de Córdoba · CIEMAT<br>
— Working mainly with Python, TypeScript, Go, PostgreSQL, queues and RAG

**Some things I've built**<br>
— [feedpulse](https://github.com/FullFran/feedpulse) — a queue-based ingestion
service for more than 10,000 RSS sources<br>
— [Hybrid-RAG-example](https://github.com/FullFran/Hybrid-RAG-example) —
semantic and keyword retrieval fused with RRF<br>
— [llm-pii-redactor](https://github.com/FullFran/llm-pii-redactor) — keeping
personal data behind the application's boundary before it reaches an AI provider<br>
— [agent-eval-tui](https://github.com/FullFran/agent-eval-tui) — local evaluation
and OTLP traces for agent runs

**What I use**<br>
Linux (Pop!_OS), Ghostty, tmux, Neovim and zsh. I keep the setup reproducible
with Nix and home-manager because rebuilding a machine should not be a ritual.<br>
I also type on a [34-key split](https://www.fullfran.com/fifi-keyboard-vial/),
which is either a useful tool or a very elaborate way of avoiding a normal keyboard.<br>
→ [fulfran-dots](https://github.com/FullFran/fulfran-dots)

**What I care about**<br>
Architecture that survives contact with reality. Systems I can still reason
about at 3am. Less magic, more engineering.
